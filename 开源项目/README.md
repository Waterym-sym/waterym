# 开源项目（调研、借鉴与二次集成）

## 1. 项目是干什么的

本目录对应工作中对**开源软件能力的调研与借鉴**，而非对外开源的公司业务产品。主要包括：

| 仓库/工程 | 用途侧重 |
|-----------|----------|
| Editor（Pascal 等） | 3D 编辑器架构、工具态、场景节点，供 3D 全流程施工借鉴 |
| nanobot | Agent / 技能 / 会话类能力参考 |
| aieditor | 富文本 / AI 编辑体验参考 |
| RuoYi / RuoYi-Vue | 后台管理脚手架与权限体系参考 |

说明：上游开源项目本身遵循各自开源协议；**公司业务侧的二次开发、配置、私有对接代码仍不可对外开源**。

## 2. 我在这个项目负责了什么

- 选型阅读、本地跑通与能力地图梳理。
- 将 Editor 能力映射到输电 3D 排位场景（见 3D 项目结合说明）。
- 按需抽取模式（工具栏、撤销、权限脚手架等）应用到业务项目。

## 3. 实际解决了哪些问题

- 从零做 3D 编辑器 / 管理后台成本高，需要**成熟参考实现**。
- Agent、富文本等新技术栈需要可运行样板，降低试错成本。

## 4. 做到了什么程度

- 本地已具备多套可运行参考工程。
- 能力已部分反馈到 3D、中后台类业务，非单独对外交付产品。

## 5. 有哪些成果

- 可对照的源码与 README / 文档阅读笔记（随业务项目沉淀）。
- 《Editor 与 tower-demo 功能结合说明》一类迁移指南。
